# 大厅与准备房间的服务端边界

## 状态

已采用。

## 决策

在单个 Colyseus 进程中注册一个 `lobby` 房间和多个按需创建的 `hearts` 房间。大厅通过 MatchMaker 查询 `hearts` 房间的公开 metadata，向客户端同步房间摘要；创建/加入操作由大厅服务端执行并返回 SeatReservation，客户端消费预约后再进入具体房间。

`hearts` 房间在 `waiting` 阶段维护房主、准备状态和机器人席位。房主及机器人始终 `ready=true`，普通玩家通过 `ready` 消息切换。房间只有在四个席位都准备后才接受房主的 `start_game`，然后依次等待所有真实玩家的 `table_ready`、发牌动画完成后的 `deal_ready`，每个阶段最多等待 30 秒；超时会回到准备阶段并重置非房主/机器人准备状态。进入对局后真实玩家有 15 秒出牌时限，机器人席位使用短延迟自动出牌；超时均从合法牌中随机代打。直接以旧协议创建的房间保留“满四人自动开始”兼容行为；大厅创建的房间标记 `lobbyManaged=true`，必须显式开始。

## 结果

准备阶段由房主通过 `set_rules` 修改 `heartsBreakingEnabled` 和 `mustDiscardPointsWhenVoid`，只接受布尔值的部分更新；两项默认开启并作为公开状态同步。实际变更会重置其他真人的准备状态，房主和机器人保持准备；开始请求锁定房间后禁止修改，后续牌局及握手回退保留选项。

- 大厅不会看到手牌、session id 或其他私有牌局数据。
- 房间列表中的人数、准备人数和阶段来自房间 metadata，而不是客户端推断。
- 客户端场景流转为 `Lobby.tscn`（连接）→ `Intro.tscn`（玩家信息与房间目录）→ `Table.tscn`。牌桌消费预约并在 `waiting` 阶段显示 Waiting，开局后显示 InGame；握手失败时清理动画和手牌并回到同一牌桌的 Waiting。`ReadyRoom.tscn` 仅保留为旧入口的跳转。离开准备阶段或结算页后返回 Intro 并重新同步存档。
- 席位编号保持固定，`playerOrder` 按席位编号排列，避免踢人后其他席位移动导致按钮目标变化。房主在准备阶段通过 `add_bot { seat }` 添加指定席位的机器人，通过 `kick_player { playerId }` 移除非房主；服务端在开始锁定期间及对局中拒绝席位管理，移除真人时释放存档占用并断开连接。准备阶段房主离开时保留房间并交接房主。
- 结算后玩家通过 `next_round` 表示同意，所有真实玩家同意后进入下一轮牌桌握手。
- 牌桌退出按钮在准备阶段与局内均可使用，并在执行前按当前身份显示确认弹窗。服务端以主动离开的连接关闭码区分退出与临时断线：开局后房主主动离开即解散房间，房客主动离开则将原席位转为机器人，保留席位 ID、手牌、分数和筹码，补齐握手或传牌并继续自动出牌。临时断线仍沿用重连与超时代打。
- 房客主动退出时，立即保存已扣除本局底注的余额并释放存档占用，可立即加入其他房间。机器人接管后，原房间的结算、回退和解散均不再写入离开玩家的存档。尚未投入底注或已完成结算时退出不额外扣款；退出扣款若保存失败，则取消未结算的牌局并退还底注。
- 房主解散未结算的牌局时，各席位退回实际投入的底注（默认 100 金币）。正常对局的底注尚未写入存档，解散时恢复房间余额与已有存档一致，不重复加款；已退出房客的弃注与原房间解除关联，不补退。已经完成结算的牌局不再退底注。
