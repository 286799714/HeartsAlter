# 服务端权威的四人红心大战回合

牌局规则、洗牌发牌、合法出牌、墩胜负、计分和筹码结算全部在 Colyseus 服务端执行；联网客户端只提交意图并渲染同步结果。手牌不放进公开状态，而是通过针对玩家的私有消息发送。这个边界避免客户端作弊，也让 Godot 客户端可以在不泄露对手手牌的情况下重连恢复。客户端保留一个明确标注的离线牌面/动画预览，用于服务器不可用时检查资源与 tween；该预览不参与联网对局，也不向服务端伪造状态。

跟牌时先检查领出花色：有同花色必须跟花色；缺门时有分牌（红桃或黑桃 Q）必须先出分牌，没有分牌才能出任意手牌。缺门出分牌的要求优先于首墩避免分牌的限制，也不受红心是否已破影响；客户端的合法牌提示与服务端校验保持一致。

本 demo 在“发牌→传牌→出牌→结算”流程中，发牌后每名玩家选择三张牌并按座位顺序传给下家；传牌选择仍由服务端权威校验和超时补选。传牌后持有梅花 2 的玩家拥有首墩领出权，但首张可选择任意合法牌。红桃按实际出牌顺序计分：黑桃 Q 打出前每张 1 点，打出后每张 2 点，同一墩内同样适用，已得分不追溯翻倍；黑桃 Q 仍计 6 点，移除射月规则。默认底注为 100，但房间可在创建时配置其他正整数底注。并列最高分玩家全部视为请客玩家；其余玩家按点数加权领取奖池，零权重或异常的边界情况使用确定性的均分回退以保证奖池守恒。

为了先用一个客户端验证完整流程，房间选项 `bots: true` 提供单人演示模式：服务端创建 3 个演示机器人，机器人仍使用同一套合法出牌与结算路径，只将其轮次响应时间缩短到约 600ms。该模式限制为一个真实连接；默认不传 `bots` 时仍要求四名真人。

教学关是明确隔离的本地练习：教学控制器以固定手牌驱动同一个牌桌场景，并复用发牌、传牌、出牌、收墩动画。牌桌在进入场景树前显式关闭联网会话绑定，教学不创建网络房间、不修改正式分数或筹码。客户端合法牌提示与教学共用 `CardRules`，并通过同一份合法出牌用例与服务端规则进行回归核对；联网校验权仍归服务端。通关记录单独写入本地教学进度文件。
